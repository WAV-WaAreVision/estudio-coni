# Plan 3b: Video production — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** After Coni approves the script and voice (gate 1), a background task renders the avatar video in HeyGen v3 without ever paying twice, burns the approved script as subtitles in Instagram's safe zone with ffmpeg + libass + Montserrat, checks the result, stores it in Cloudflare R2 and moves the piece to `video_por_aprobar`.

**Architecture:** Same layering as Plan 3a. `lib/proveedores/heygen-api.ts` (HTTP v3), `lib/proveedores/almacen.ts` gains the real R2 implementation, `lib/video/` holds ffmpeg/ffprobe wrappers and pure video checks, `lib/produccion/grabar.ts` orchestrates with injected dependencies, `trigger/grabar-pieza.ts` is the thin Trigger.dev task (wait token for HeyGen's callback). Writes go through the database as `service_role`; Plan 2's triggers still guard the gates.

**Sources:** design doc (`~/Projects/coni-heygen/docs/designs/plataforma-coni.md`): "Piezas técnicas" (Video, Subtítulos, Chequeos del video, Almacenamiento), "Reintentos seguros", A10 (callback only wakes the task; always read the video status by id; token timeout 60 min), Q3 (Montserrat, explicit `fontsdir`, `fontselect` check), P1 (`medium-1x` or larger), D5 (R2 private, signed URLs, retention). `scripts/coni.py` lines 471-517 (`bajar_srt`, `cmd_subtitulos`, ffmpeg arguments, 32 MB HeyGen asset limit). HeyGen evidence from `coni-heygen`: `POST /v3/videos`, `GET /v3/videos/{id}` (fields `id`, `status`, `duration`, `video_url`, `subtitle_url`, `failure_code`, `failure_message`), asset upload for Ruta B audio. Plan 1/2/3a execution notes.

**Rules specific to this plan:** HeyGen only through v3 endpoints (repo rule: no v1/v2). Verify every HeyGen path, header and field against the official docs (`https://developers.heygen.com` reference pages) with WebFetch before writing the adapter, and cite the doc URL in a comment above each call; if a needed capability (asset upload, callback URL) has no v3 endpoint, stop and report BLOCKED instead of using v1/v2. Do not download fonts or binaries: the Montserrat file is added by the controller; tests that need it skip with a clear message when it is absent. Never call real HeyGen, R2 or ElevenLabs; MSW and fakes only.

**Files:** `lib/proveedores/heygen-api.ts`, `tests/unit/heygen-api.test.ts`.

### Task 4: `grabar-pieza` orchestration and task

**Files:** `lib/produccion/grabar.ts`, `lib/datos/repositorio.ts`, `trigger/grabar-pieza.ts`, `trigger.config.ts`, `supabase/migrations/20261001001000_grabacion.sql` (only if columns are needed), `tests/integration/grabar.test.ts`.

`grabarPieza(deps, piezaId)`, deps = `{ db, heygen: { clave }, almacen, quemar, sondear, esperarRender: (videoId) => Promise<void>, callbackUrl?: string, ahora }`:
1. Read the piece. Not `en_render` → `{ resultado: "nada_que_hacer" }`. `puedeGrabar(pieza, hashPuerta1({ guion, audioId }))` not ok → record nothing, return `{ resultado: "sin_aprobacion" }` (never spend).
2. If `render_id` is set (a previous attempt already created the video), skip to step 5: never `POST /v3/videos` twice for the same attempt. Note Plan 3a: `cambiar_guion`/`regrabar` keep a stale `render_id`; clear it when entering `en_render` from `video_por_aprobar` (regrabar) — add that to the write in this task or a DB rule, and test it.
3. Reserve HeyGen spend: key `claveIdempotencia({ piezaId, paso: "grabar", hash: puerta1.hash, intento })`, estimate from `estimarSegundos(guion)` × a documented credit rate assumption (avatar_v 48 credits/min; record the USD-per-credit assumption as a constant). `tope_alcanzado` → `explicacion`, return `{ resultado: "tope" }`. Confirmed/liberado reservation for this key → do not create again.
4. Read Coni's HeyGen key (`leer_secreto("heygen")`), download the voice from storage (`audioId`), `subirAsset`, `armarPedido({ config, guion, titulo, audioAssetId })`, `crearVideo` with `callbackUrl`, then immediately write `render_id` (version + 1) before waiting. Policy rejection on create → `transicionar(..., politica_contenido)`, release spend, return.
5. `await deps.esperarRender(videoId)` (the task passes a Trigger.dev wait-token wait with 60 min timeout; the callback only wakes it), then ALWAYS `leerVideo` (A10). `pendiente`/`procesando` after the wait → plain `Error` (retry re-reads). `fallido` with policy code → `politica_contenido` + release; other failure → `falla_produccion` with a Coni-facing explanation + release.
6. `listo` → `transicionar(render_entregado)` (→ `subtitulando`) and confirm the spend; download the video and the SRT (`subtitleUrl`), `alinearConGuion(leerSrt(srt), guion)` → `assDe` → `quemar` → `sondear` → `revisarVideo`; blocking finding → `falla_produccion` ("El video no pasó los chequeos: ..."); else upload to `videos/<piezaId>/<sha256>.mp4`, `transicionar(video_listo, { videoId: clave })`. The raw HeyGen video is not stored (design: raw deleted after burning).
7. Any `Falla` after `subtitulando` → `falla_produccion` with its message. `FallaDeConfiguracion` → rethrow.

### HeyGen v3 pages used (all read with WebFetch before the adapter was written)

- Authentication, header `X-Api-Key`: https://developers.heygen.com/docs/api-key.md
- `POST /v3/assets`, multipart field `file`, 32 MB, `{ data: { asset_id } }`, optional `Idempotency-Key`: https://developers.heygen.com/reference/upload-asset.md
- `POST /v3/videos`: `audio_asset_id`, `callback_url`, `callback_id`, `caption.file_format`, `Idempotency-Key` header (replays the first answer for 24 h; a retry while the first is in flight gets 409 `request_in_progress`), answer `{ data: { video_id, status: "waiting" } }`: https://developers.heygen.com/reference/create-video.md
- `GET /v3/videos/{video_id}`: `{ data: { id, status: pending | processing | completed | failed, video_url, subtitle_url, duration, failure_code, failure_message } }`: https://developers.heygen.com/reference/get-video.md
- Error body `{ error: { code, message, doc_url } }` and the codes by HTTP status (`content_policy_violation` is a 400): https://developers.heygen.com/docs/error-codes.md
- Webhook payloads (`event_type`, `event_data.video_id`, per-request `callback_url`, "query `GET /v3/videos/{id}` for failures"): https://developers.heygen.com/docs/webhooks.md and https://developers.heygen.com/docs/webhook-events.md
- Quick start (statuses `generating | completed | failed` in its polling flow): https://developers.heygen.com/docs/quick-start

No v1/v2 endpoint is used and nothing was BLOCKED: asset upload and the per-request callback both exist in v3. Gaps in the docs, handled on the safe side: the `failure_code` values of a failed video are not listed anywhere (only the 400 `content_policy_violation` of the create call is), so a failed video is matched against that same code; the three pages disagree on the in-progress status (`waiting`, `pending`, `generating`), so all of them read as "not finished yet" and an unknown status is a plain `Error` that the retry reads again.

### Deviations

- Task 1: `crearVideo` and `subirAsset` also take `idempotencia` and send it as `Idempotency-Key` (documented for both endpoints). It is the second line of defence of "never pay twice": the first is the stored `render_id`. `leerVideo` returns a discriminated union (`listo` always carries `videoUrl`). Error classes: `content_policy_violation` anywhere is `PoliticaDeContenido`; 401, 403 and every other 4xx except 402, 408, 409 and 429 are `FallaDeConfiguracion` (same rule as ElevenLabs); 402 is a `Falla` written for Coni ("Tu cuenta de HeyGen no tiene créditos..."), which the plan did not list but she is the one who can fix it; 408, 409, 429, 5xx and network are plain errors. `bajar` never puts the signed query in a message.
- Task 2: `Almacen.urlFirmada` checks that the object exists (a HEAD) in the R2 implementation, so the in-memory double and the real store keep one contract, and both refuse a lifetime that is not a whole number of seconds up to 7 days. Path-style on the account endpoint (`forcePathStyle`), and `requestChecksumCalculation: "WHEN_REQUIRED"` because R2 does not accept the SDK's default `aws-chunked` trailers (a test fails with the default). MSW's node interceptor does cover the SDK; no custom handler was needed. R2 errors are rebuilt from name, status and message (no `cause`), with the key and secret redacted. `claveVideo` is `videos/<piece>/<sha256>.mp4`, next to `claveAudio`.
- Task 3: `buscarFfmpeg` also tries `FFMPEG_PATH`, which Trigger.dev's `ffmpeg()` extension sets in the container, and `buscarFfprobe` uses `FFPROBE_PATH`, then the ffprobe next to the ffmpeg. ffmpeg runs in a temporary folder with `fontsdir=fuentes`, a symlink to the real folder, so no path ever needs escaping in the filter (coni.py does the same with the working directory). `exigirMontserratBold` runs `fuenteElegida` with a cue of its own and fails with a `FallaDeConfiguracion` unless libass picks `Montserrat-Bold`; `depsGrabacion` calls it at the start of every run, before anything is reserved. Observed `fontselect` lines on this Mac (ffmpeg 9.0.2, CoreText): with `fontsdir=assets/fuentes`, `fontselect: (Montserrat, 700, 0) -> Montserrat-Bold, 0, Montserrat-Bold`; without it, `fontselect: (Montserrat, 700, 0) -> /Users/fede/Library/Application Support/Adobe/CoreSync/plugins/livetype/.r/.37470.otf, -1, Montserrat-Black`, which is the silent variant swap of Q3. The Linux (fontconfig) line has the same shape with a file path in place of the name; it has not been observed. libass also tries to load `OFL.txt` from the folder and logs "Error opening memory font"; it is harmless. Montserrat Bold and its OFL license are committed (added by the controller, sha256 bc6e8549...ec61).
- Task 4, states: `grabarPieza` also resumes a piece in `subtitulando` (the plan returned `nada_que_hacer` for anything but `en_render`, which turned a retry after an ffmpeg failure into a successful no-op with the piece stuck). It reads the stored `render_id`, skips the gate (nothing is spent any more) and does not wait. Results beyond the plan: `grabada`, `politica_contenido`, `falla_produccion`.
- Task 4, `render_id`: the stale id is cleared by a database trigger (`limpiar_render`, migration `20261001001000_grabacion.sql`) on every entry into `en_render`, not by the task: the writes that enter it are Coni's (approval, Regrabar, Reintentar). Clearing only on Regrabar, as the plan said, would leave a retry after a failed render, or a re-approval after a policy rejection, reading the dead video for ever. A retry from `error_produccion` that came from `subtitulando` keeps the id.
- Task 4, retries: a stored render is read before waiting (the callback of the first attempt went to that run's token, which a later run may not share), so a finished video is not waited for. The task creates its wait token with `idempotencyKey: render-<run id>`, so the attempts of one run share it. The HeyGen key is read from the Vault inside `grabarPieza` (the plan listed `heygen: { clave }` among the deps). The piece moves first and the spend is released after (policy and failures), so a crash in between leaves a reservation for the sweeper rather than a piece stuck in render. A `Falla` anywhere (a 402, a script the SRT does not match, a missing SRT, failed checks) ends the attempt with `falla_produccion` and its message; a plain error or a configuration error is rethrown with the spend left reserved. A reservation that is not `reservado` and has no `render_id` is a `FallaDeConfiguracion`: it never creates a second video.
- Task 4, assumptions: the HeyGen estimate is `segundos / 60 × credits per minute × USD per credit`, with 48 credits a minute for `avatar_v` and 16 for Avatar IV, and US$ 4 a minute of `avatar_v` (the top of the design's open question 5, US$ 3 to 4 per minute) as the USD-per-credit assumption; the confirmed amount equals the estimate. The callback is `callback_url` of `POST /v3/videos` set to the wait token's URL; HeyGen's payload is ignored on purpose (A10). `trigger.config.ts` sets `legacyDevProcessCwdBehaviour: false` so `process.cwd()/assets/fuentes` is the fonts folder in dev and in the container (`CONI_FONTSDIR` overrides it). The production behaviour of the token URL, `additionalFiles` and the apt ffmpeg could not be exercised without a Trigger.dev deploy.
- Shared helpers (`aCuatroDecimales`, `MINIMO_USD`, `TEXTO_TOPE`, `piezaCambio`, `explicar`) moved from `producir.ts` to `lib/produccion/comun.ts`, now that two callers use them.

### Carried to Plan 4

- Nothing moves a piece when a run exhausts its retries: a video still rendering 60 minutes after the wait (the design says `error_produccion`; the task throws, so the run fails and the piece stays `en_render`), a persistent plain error while burning (the piece stays `subtitulando`) and a `FallaDeConfiguracion` all leave it there without an `explicacion`. `mantenimiento` must reconcile `en_render` pieces older than 15 minutes (read the video by `render_id`, or move to `error_produccion`) and also `subtitulando` ones; an `onFailure` hook should write a generic explanation and alert WAV.
- Who triggers `grabar-pieza`: after Coni's gate 1, after Regrabar, after a Reintentar into `en_render` or `subtitulando`, and after she raises the cap (`tope` returns normally with the piece still `en_render`). Use an idempotency key per piece and `intento`.
- Stale `reservado` HeyGen rows (a crash between moving the piece and releasing the spend) need the sweeper already carried from Plan 3a; HeyGen usage is not read back, so the confirmed amount is the estimate.
- R2 retention jobs: voices of discarded pieces, final videos of discarded pieces after 30 days (design D5); the raw HeyGen video is never stored.
- A run that creates the video and dies before it stores `render_id` relies on HeyGen's 24-hour idempotency window; a retry later than that would pay twice. Trigger.dev retries are minutes apart, but a manual re-trigger a day later is not covered.
- The `failure_code` values of a failed video, the Linux `fontselect` line and the callback path through Trigger.dev's token URL should be checked once against the real services.
