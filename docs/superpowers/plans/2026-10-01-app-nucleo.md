# Plan 5a: App core (login, Inicio, Guion, Video) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Checkbox steps.

**Goal:** Coni signs in with an emailed code from the installed PWA, sees what needs her signature, approves scripts (gate 1) and videos with a date (gate 2) by sliding, and every action reaches the database through authenticated Server Actions that run the domain state machine and trigger the background tasks.

**Design (approved, binding):** `docs/DESIGN.md` (tokens, components, rules), `docs/PRODUCT.md` (users, principles, a11y), `docs/estudio-coni-propuestas.html` (directions marked "Elegida": Inicio = lista serena; Guion = carta on the pillar tint, pillar strip on top, "Si lo apruebas hoy, sale el ..." line; Video = full-bleed 9:16 player, review panel appears after watching to the end) and `docs/estudio-coni-propuestas-2.html` (Ingreso = six OTP boxes). Design doc `~/Projects/coni-heygen/docs/designs/plataforma-coni.md` "Design Review" section: information architecture (Pass 1), states table (Pass 2), journey (Pass 3), a11y (Pass 6), 3-tab nav Inicio/Métricas/Ajustes. Load the `impeccable` and `emil-design-eng` skills before writing UI. Young Serif only for titles and the script; Hanken Grotesk for everything else; 18 px base; 52 px primary buttons; 44 px targets; raspberry `#b3285f` is the only action color; no `#fff`/`#000`; no em dashes in copy; light theme.

**Architecture:** Next.js 16 App Router (check `node_modules/next/dist/docs` for v16 specifics, e.g. `proxy.ts` replacing `middleware.ts`, async `cookies()`), Tailwind v4 tokens in `app/globals.css` from DESIGN.md, `next/font/google` for the two families. Server Actions in `app/(app)/**/acciones.ts` call `lib/acciones/*.ts` (pure-ish functions with injected `db` + `disparar` so they are unit/integration testable). Approvals run as Coni (her session's Supabase client) so the DB triggers record her; tasks are triggered with `tasks.trigger` from `@trigger.dev/sdk` using global idempotency keys (`claveIdempotencia`).

### Task 1: Shell, tokens, fonts, PWA
`app/layout.tsx` (lang `es-CL`, metadata "Estudio de Coni", viewport, theme color), `app/globals.css` with DESIGN.md tokens as CSS variables + Tailwind v4 `@theme`, `app/manifest.ts` (standalone, icons placeholder generated as simple SVG/PNG from tokens), `components/nav-inferior.tsx` (Inicio, Métricas, Ajustes; Métricas/Ajustes routes render a placeholder "Muy pronto" until Plan 5b), base components from DESIGN.md: `Boton`, `PildoraPilar`, `MarcaRevision`, `Aviso` (toast). Remove the template page. Test: render tests (Testing Library) for components (accessible names, 44 px min via class), `pnpm build`. Commit "feat(app): shell, design tokens and PWA manifest".

### Task 2: Sign-in with an emailed code
`app/ingreso/page.tsx` + `lib/acciones/ingreso.ts`: step 1 shows the masked email and "Mandarme el código" (single user; the server only accepts the address in `AVISOS_CORREO_CONI`/`CORREO_CONI`, and `signInWithOtp({ email, options: { shouldCreateUser: false } })`); step 2 six boxes (`autocomplete="one-time-code"` on the first, numeric keyboard, paste fills all), `verifyOtp({ email, token, type: "email" })`, then redirect to `/`. Session refresh in `proxy.ts` (or `middleware.ts` if v16 docs say so) with `@supabase/ssr`; every `(app)` route requires a session whose user is Coni (`es_coni()`); the maintainer and anyone else get a plain "Esta app es solo para Coni." page. Local config: Supabase email OTP enabled with 6 digits in `supabase/config.toml`; seed Coni's email. Errors from the states table (wrong/expired code, too many attempts). Tests: unit for code-box behaviour; integration/E2E (Task 6) does the real OTP through the local mail catcher (Mailpit/Inbucket API on port 54424). Commit "feat(app): sign in with an emailed code".

### Task 3: Server Actions core
`lib/acciones/piezas.ts` with injected `{ db (Coni's client), disparar, ahora }`: `elegirIdeas(ids)` (creates pieces from ideas, `elegir` transition, marks ideas `usada`, triggers `producir-pieza`), `aprobarGuion(piezaId, versionVista)` (reads row, recomputes `hashPuerta1` from the row, `transicionar(aprobar_guion)` with `hashVisto` = hash of what the screen showed (passed from the client as the version she saw → refuse if `version` changed), update with version check, trigger `grabar-pieza`), `pedirCambios`, `editarTexto(texto)` (runs `revisarGuion` deterministic inline and stores the new revision through a service-role helper since only the server writes `revision`; caption-only edit per R2-5), `aprobarVideo(piezaId, versionVista, publicarEn)` (date in `America/Santiago` converted to UTC with an explicit offset; must be in the future), `regrabar`, `cambiarFecha`, `descartar` (cancel effect: if `programado`, nothing remote to cancel with Graph API direct; document), `reintentar`. Every action catches `Falla` and returns `{ error: mensaje }` (Next redacts thrown messages); `FallaDeConfiguracion`/`AprobacionNoAutorizada`/unknown → generic Spanish error + server log. CRLF→LF and NFC normalization of edited text at this boundary (carried). Integration tests against local DB with a fake `disparar`: each action's happy path, stale version → error message, approvals recorded with Coni's id, service-role cannot be used by these actions, blocking review → refused. Commit "feat(acciones): server actions for the two gates".

### Task 4: Inicio
`app/(app)/page.tsx`: "Hola, Coni", week summary, "Necesita tu firma" list (guion / video rows open the detail; no approve buttons in the list, A11), "En camino" (grabando/programado with progress hint), "Ideas de la semana" (5 suggested ideas, choose 3 → `elegirIdeas`), consultas counter placeholder (Plan 6). States from the Pass 2 table: skeleton loading, empty ("Nada espera tu firma esta semana..."), error notice with cause and action, success notices, partial. Commit "feat(app): inicio".

### Task 5: Guion and Video screens
`app/(app)/guion/[id]/page.tsx`: pillar strip, title in serif, "Si lo apruebas hoy, sale el ..." line, the script as a letter on the pillar tint (Young Serif), voice player (signed R2 URL via service-role server helper, never exposing keys), "Así sale en Instagram" with the caption (editable → `editarTexto`), review findings (`MarcaRevision`: bloquea items must be fixed; advierte items need "Lo revisé y está bien" ticks), cost line, slide-to-approve (`input type=range`, approves at 96 %, `aria-valuetext`, keyboard End) disabled until the voice was played and warnings confirmed and no blocking findings; "Pedir cambios". `app/(app)/video/[id]/page.tsx`: full-bleed 9:16 player with "Avatar IA" label and "Ver zonas de Instagram" toggle, review panel appears after 95 % watched (no forward seeking counted), checklist, caption, proposed date (next Tue/Thu/Sat 19:00 Santiago, editable), slide "aprobar video y fecha", "Regrabar". Commit "feat(app): guion and video screens with slide to approve".

### Task 6: E2E and verification
Playwright at iPhone viewport against `next start` + local Supabase: sign in through the real OTP (read the code from the local mail catcher API), see a piece seeded in `guion_por_aprobar` (seed helper as service role), play voice (mock media), confirm warnings, slide to approve → piece `en_render` and a fake trigger recorded (inject a test `disparar` via env `DISPARO_DE_PRUEBA=1` that writes to a table or log; never call Trigger.dev); video gate likewise. Run lint/type/test:run/test:db/build/e2e. Append "Execution notes". Commit "test(e2e): coni approves script and video".

## Execution notes (2026-10-01)

The code on `feat/app-nucleo` is the source of truth; these deviations supersede the plan text above. Final counts: 853 unit tests (745 before), 302 integration tests (265 before), 15 Playwright tests (new). `pnpm lint`, `pnpm type`, `pnpm test:run`, `pnpm test:db`, `pnpm build` and `pnpm test:e2e` were run separately and are clean. Nothing real was called: no Trigger.dev, Meta, HeyGen, ElevenLabs or R2, no cloud resource, no push.

### Deviations

- Task 1: tokens are CSS variables in `app/globals.css` (hex only there, as DESIGN.md gives them) and Tailwind names such as `bg-fondo`, `text-tinta`, `bg-acento`; pillars derive their four colours from `data-pilar` with OKLCH. Base components: `Boton` (`aria-disabled` instead of `disabled`, so a disabled approve control stays focusable and says why), `PildoraPilar`, `MarcaRevision`, `Aviso` (an `<output>`, Biome's a11y rule), `NavInferior` (steps aside on `/guion/*` and `/video/*`, where the approve bar owns the bottom). Icons are `app/icon.tsx` and `app/apple-icon.tsx` (ImageResponse, her initial on the action colour) instead of static files, and the manifest lists 512 and 180 px only (iPhone is the target). `app/favicon.ico` of the template is gone. `clasesDeBoton` lives in `components/ui/clases-de-boton.ts`: it was exported from the `"use client"` file and called from Server Components, which type and build accepted and Inicio answered with a 500 the first time its empty state rendered; the E2E caught it. The commit of Task 4 was amended with the fix.
- Task 2: `signInWithOtp` needs `{{ .Token }}` in the magic-link template, so `supabase/config.toml` points `[auth.email.template.magic_link]` at `supabase/templates/codigo.html` and raises `email_sent` to 100 (local only). The seed users had NULL token columns and GoTrue answered "Database error finding user" on sign-in (the carried item about local sign-in): `supabase/seed.sql` now writes empty strings. No email box anywhere: the address comes from `CORREO_CONI` (or `AVISOS_CORREO_CONI`), is shown masked (`c•••@dominio`) and never travels from the browser. The six boxes submit by themselves when full, accept paste and the iOS one-time-code fill, and a wrong code empties and re-focuses them. The gate is two layers: `proxy.ts` (optimistic, session only) and `leerSesion()` (`es_coni()`), which the `(app)` layout and every page and Server Action call again; anyone else sees "Esta app es solo para Coni." with a Salir button.
- Task 3: all the actions live in one file, `app/(app)/piezas/acciones.ts`, instead of one `acciones.ts` per route (the screens share them); each action validates its input with zod, checks the session and calls `lib/acciones/piezas.ts` with injected `{ db, servicio, disparar, ahora }`. Results are `{ ok: true, ... } | { ok: false, error }`. `aprobarGuion` and `aprobarVideo` refuse any `versionVista` that is not the row's version (the write is guarded by the same version, so the hash taken from the row is the hash of what she saw) and refuse while `revision` has a blocking finding, with the finding's own message. Two actions beyond the plan: `reintentarGuion` (a piece left in `guion_en_proceso` with a reason: clears it and starts the script again; the run key includes the piece version, so it is never the key of the run that stopped) and a check in `aprobarVideo` that no other scheduled piece has the same minute. Idempotency keys: `producir` = piece + hash of the round (`version`) + `intento`; `grabar` = piece + hash of gate 1 + `intento`; Trigger.dev gets them with `idempotencyKeys.create(clave, { scope: "global" })`. If Trigger.dev cannot be reached after an approval, the approval stands and Coni gets a warning (the piece is saved first); if it cannot be reached when she chooses ideas, the piece gets a reason she can read and `reintentarGuion`. Integration tests use a real Auth session (admin `generateLink` + `verifyOtp`), so row level security and the triggers answer as they do in production, plus the maintainer and `service_role` as `db` to prove neither can approve.
- Task 4: the five ideas of Inicio are chosen by `sugerirIdeas` (pillars that came out least in the last 30 days first, one per pillar before repeating, then strength and number). There is no Monday 8:00 job yet, so they are computed on every visit. "Consultas" is a one-line placeholder (no counter, no fake number). Offline: a bar says "Sin conexión. Aprueba cuando vuelva." instead of the design's "lo que apruebes se envía al volver": nothing is queued, so it does not promise that.
- Task 5: section titles are sentence case and there are no small-caps kickers (DESIGN.md overrules the mockup's CSS). The video review is the single tick "Revisé labios, nombre, subtítulos y cortes" of the chosen direction, not four. "Watched" and "listened" are the same rule (`lib/medios/visionado.ts`): 95 percent of contiguous natural playback from the start, jumps forward not counted, remembered in `localStorage` per stored file. The voice needs the same listening as the video (a 46 s script). `Pedir cambios` and `Regrabar` ask once inline ("¿Seguro?") because both spend money or discard work next to the main control. The date list offers the next four free slots (Tue/Thu/Sat 19:00 Santiago, one hour of lead), not a free date picker. "Si lo apruebas hoy, sale el ..." takes the first free slot after a 12 hour lead and after the pieces already ahead in the pipeline. The cost line (`Grabar cuesta unos US$ 2,40 · te quedan US$ 37,00 este mes`) is left out when `ajustes.produccion` cannot be read, rather than a wrong number. Pieces that are not waiting for a signature show their state (writing, recording, failed with Reintentar, scheduled with Cambiar la fecha, published) instead of the approve controls.
- Task 6: Playwright drives Chromium with the iPhone 14 device settings (390 x 844) against `next build` + `next start` on port 3200 and the local stack. The Chromium revision this Playwright version wants is not installed on the machine and nothing was downloaded: `PLAYWRIGHT_CHROMIUM_PATH` points at an installed one. The sign-in code is read from the local mail catcher (Mailpit, 54424); the runs the app would start are written to `test-results/disparos.jsonl` by `DISPARO_DE_PRUEBA=1` (refused when `VERCEL` is set, unit-tested); the signed R2 links are `https://almacen.test/...` and the test answers them with two small real files (WAV and WebM). The specs cover the sign-in (wrong code, then the right one), Inicio (with work, empty, a failed piece, choosing three ideas), the script gate (slide disabled until she listens and confirms, End key approves, caption without the avatar notice blocks, a screen made stale does not approve, Pedir cambios), the video gate (watch to the end, tick, pick the second date, drag the thumb with the pointer; skipping to the end does not count; Regrabar; Cambiar la fecha) and the maintainer and no-session cases.

### Carried to later plans

- A render that Coni approved but whose `grabar-pieza` run never started stays in `en_render` without a reason: `conciliarRenders` only gives up after an hour and does not start it. Let the reconciler start `grabar-pieza` (same key as the action) for an `en_render` piece with no `render_id` and no reason after a few minutes.
- `editarTexto` writes `revision` as `service_role` (only the server may), so its audit row has no user. An `editar_texto` SQL function (`security definer`, `es_coni()`, version check) would keep Coni as the actor.
- Production setup that the local config does not carry: the magic-link email template with `{{ .Token }}` in the hosted Auth settings, an email rate limit that fits `max_frequency` (the app reads the seconds from Supabase's message), `CORREO_CONI`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TRIGGER_SECRET_KEY` and the R2 variables in Vercel. `DISPARO_DE_PRUEBA` must stay unset there.
- Not exercised on a real iPhone: VoiceOver, inline media and autoplay rules of iOS Safari, the Mail one-time-code autofill, thumb dragging by touch, Dynamic Type. Chromium emulates the viewport, not those.
- Not built from the design review: the install sheet and push permission (Pass 3 step 2), the first-time avatar message, the 08:30 digest and 48 hour reminders (they need the notifications table), "Ver todas las ideas" and the calendar link on Inicio, the idea bank screen, a free date picker. `Métricas` and `Ajustes` are "Muy pronto" pages for Plan 5b, including "Conectar Instagram" (`meta_cuenta_id` and `meta_token_expira_en` are still Plan 5b's).
- CI has no E2E job: it needs `supabase start` and a browser. `pnpm test:e2e` is local. `pnpm build` passes in CI without the public variables (every page that reads the session is dynamic).
- While the work ran, Docker's VM (Colima) stopped and came back; the stack restarted from its backup with the data intact. Other Supabase stacks on the machine were started by another session and were not touched.
